# Agent 采集流程（scrape-flow）

**为什么存在**：把"探路+抓取+解析+报告"塞给一个 agent 从零做，会在错误的入口死磕、解析崩了全部重抓、单线程慢。本流程用阶段检查点把这些浪费挡住。核心三律：

1. **探路不通过，不铺开**（阶段 0/1 是闸门）
2. **先存原始，再解析**（解析代码崩了不用重新抓）
3. **批量交给脚本，agent 只管异常**（agent 写循环是最贵的循环）

## 阶段 0：侦察（probe）—— 限时 10 分钟

**逐采集单元探路**：同一学校的不同学院名录形态可能完全不同（单页大表/按系分页/按职称分栏/照片墙并存——NWPU 实测一校 4 种），不要用第一个单元的形态套其余单元。

只回答三个问题，不抓数据：

1. **入口在哪**：目标站点的列表页 URL（导师名录/师资队伍栏目）。2-3 个候选入口都要记下来。
2. **页面形态**：用 `curl -s -k -A "Mozilla/5.0" <url> | head -100` 看返回：
   - 静态 HTML（能看到目标人名/字段）→ 走 HTTP 快车道
   - 空 div + JS bundle → JS 渲染站，进坑清单查隐藏 API 线索
   - 403/412/跳验证页 → 反爬：412 多为 JS cookie 挑战型 WAF（无浏览器**不绕过**，走 pitfall 降级链换字段来源），403 先查 UA 与频率
3. **有没有更硬的数据源**：HTML 里 grep `api|json|getData|fetch(|generalQuery|showTitle`——很多站列表是 JSON 接口吐的（Sudy WP 站群的 `/_wp3services/generalQuery`、藏在页面 JS 变量数组里的 qh_data），直接调比解析 HTML 稳一个数量级。
4. **同站多视图名录必须比对各视图总条数再选**（按拼音/按单位/按职称视图常有出入，"按职称"未必最全——复旦实测按职称版仅 27 人、按单位版 194 人）。响应体只有 1-2KB 且含 `window.location.href` 的是 JS 壳页，跟跳转。

产出 `probe.md`：入口清单 + 每个入口的形态标注 + 选定路线。**这一步的产出决定后面全部效率，值得花满 10 分钟。**

## 阶段 1：试点（pilot）—— 单条端到端

抓**一个最小单元**（一页/一个学院），走完 抓取→落原始→解析→出 1 条 schema 样例 全链路。样例不过关（字段缺、乱码、错位），回阶段 0 换路线，**不带着问题铺开**。

## 阶段 2：批量抓取（fetch）—— 脚本跑，agent 盯

- 把试点验证过的请求逻辑写成脚本循环（python urllib 即可），**原始响应按单元落盘** `raw/`（HTML 原样存，或 JSON 原样存），同时写 `done.json`（已成功 URL 列表）
- **翻页一律跟随页面上的"下页/下一页"链接链式走，禁止按页码算术 +1 递增**——倒序编号分页（NWPU 实测）会让 +1 直接漏页。但两个附加防御（USTC 实测）：
  - **假分页检测**：相邻页内容签名（正文哈希/条目数）相同则停止——Sudy 站存在 list1/2/3.htm 内容完全相同且"下一页"循环链接的假分页，照走会三倍重复
  - **终止识别**：尾页"下一页"常为 `javascript:void(0)` 或 `#`——urljoin 会把 void(0) 当绝对 URL 返回，必须先识别终止符再 urljoin
- 断点续跑：脚本启动时读 `done.json` 跳过已抓单元——崩了重跑不重抓
- 频率红线：单域名间隔 ≥2s；429/403 出现立即停，间隔翻倍或换时段
- agent 的角色是看日志、处理异常单元，不是替脚本循环

## 阶段 3：离线解析（parse）

- 对 `raw/` 跑解析脚本（与抓取解耦）：编码自适应（国内站常见 **GBK/GB2312**，先探测再解码）、字段抽取、schema 化
- 解析失败的单元记入 `parse_errors.json` 带原因，不阻塞全量
- 产出 `parsed.jsonl`（每单元一条，便于增量重解析）

## 阶段 4：合并、diff、报告

- parsed 去重合并 → 目标 schema
- 与存量数据 diff（如有）
- 报告：抓取情况表（入口/形态/条数/异常）、问题清单、对流程本身的改进建议（回写 `pitfalls.md`）

## 工具梯子（从上往下试，别跳级）

1. `curl -k -A "Mozilla/5.0 ..."`（-k 过自签/过期证书，高校站常见）
2. python `urllib.request`（可编程循环、可控间隔）
3. 站内隐藏 JSON 接口（阶段 0 发现的）
4. **多模态图像分析（图片化数据源时优先于浏览器）**：整页 JPG 的研招目录、图片化邮箱/名单、照片墙——把图片的**远程 URL** 喂给多模态分析工具（主会话有 `mcp__4_5v_mcp__analyze_image`，仅支持远程 URL，不支持本地文件），prompt 明确要求转写图中全部文字/名单。西工大"研招目录整页 JPG 无 OCR 放弃"的旧结论作废——现在能读
5. 浏览器自动化（最重最慢，只在确实 JS 才能渲染时用；一次会话抓完缓存，别每页开浏览器）

## 常见坑速查

详见 `references/pitfalls.md`（含国内高校站专项清单与实测标注，**跑完任务必须回写新坑**）。高频摘录：

- GBK 编码 → `resp.decode('utf-8')` 失败时试 GBK，或按响应头/`<meta charset>` 探测
- HTTPS 证书过期 → curl 加 `-k`，python 加 `ssl._create_unverified_context()`
- **412 = JS cookie WAF**（教师主页系统常见）→ 不绕过，按降级链换字段来源（学院页邻接文本 → 英文站 → 领导页 → 搜索逐人核实，记 `name_source`）
- 分页参数藏在 POST 表单 → 第一页 HTML 里的 `<form>` 就是答案
- 列表页字段不全（只有名字）→ 名字+URL 先抓全，详情页第二遍补字段
- WAF 拦截页长得像正常页（返回 200）→ 校验内容里真有目标字段再算成功
- **HTML 正则一律加 re.I**（大写 `<A>` 漏链，NWPU 实测）
- 中文站空白、英文站拼音名 → 拼音恢复链，恢复不了保留拼音入库待人工补

## 并行策略

多个**互不依赖的入口**（不同学院子站、不同学校）可并行成多个子任务，每个子任务独立走阶段 0-4，产出汇总到同一目录。单入口内部不要并行（频率红线）。

**并发上限（实测教训）**：子代理并发 **≤4**——38 并发实测触发 API 限流（1302），8 并发仍会死亡，4 并发全程稳定。大批量任务用滚动补派（每完成一个补一个）而非一次全发。**网络层 fetch failed 是常态**（38 校实测 5 例）：断点续跑 + 失败现场盘点（近完成改派"收尾模式"纯组装零网络请求）+ 指数退避 + 每单元即时落盘。
