# PITFALLS — advisor-social-mining（2026-10-02 实测）

**跑完任务必须回写新坑**（沿 scrape-flow 惯例）。标注 [实测] 的都是 IAB 真机验证过的事实。

## 知乎

1. **[实测] 未登录搜索是"假空结果"**：`zhihu.com/search?type=content&q=...` 页面框架正常、tab 齐全，但一律显示"未搜索到相关内容"——连"考研"这种超高频词也如此。**看到空结果先检查是否登录，别当真**。curl 未带 cookie 直接 403，同理别用 curl 探知乎搜索。
2. **[实测] 问答页+评论区匿名全可读**：问题页正文、回答、作者、日期无需登录；点回答下"X 条评论"展开后，评论者昵称、内容、日期全可见（页面还会显示"未登录用户 2 条评论"字样，不影响读取）。
3. **[实测] 评论按钮 role 点击必超时**：`getByRole("button", { name: "X 条评论" })` 存在且唯一，但 click 3s 内超时（疑似视口外不可达，IAB 不自动滚动）。**可靠做法是 JS 点击**：
   ```js
   await tab.playwright.evaluate(() => {
     const b = Array.from(document.querySelectorAll("button"))
       .find(x => x.textContent.includes("条评论"));
     if (b) { b.scrollIntoView({ block: "center" }); b.click(); }
   });
   ```
   点击前 `waitForLoadState("domcontentloaded")` + 页面刚加载完时第一次点击可能撞上渲染竞争，等 2-3s 再点。
4. **[实测] Bing `site:zhihu.com` 可用**，能返回真实 question id 直链。小红书同理搜不到——见下。
5. 子回复"展开其他 N 条回复"同样是 JS 渲染，展开逻辑同上；评论区随滚动懒加载，快照前先滚动到位。

## 小红书

6. **[实测] 全站登录墙**：搜索页弹窗"登录后查看搜索结果"，首页/发现页弹窗"登录后推荐更懂你的笔记"+全屏遮罩。没有匿名浏览的口子。登录弹窗自带 `textbox "+86"` 手机号输入——就是登录入口。
7. **[实测] 搜索引擎完全不收录**：Bing `site:xiaohongshu.com` 会无视 site: 过滤返回无关结果（说明索引里几乎没有 xiaohongshu.com 页面）。**小红书内容发现只有站内搜索一条路**，而站内搜索需要登录。
8. 登录滑块/风控：agent 代填手机号+验证码时**可能**撞滑块。**连续失败 2 次立即转用户手动登录模式**，硬刚会加重风控甚至触发账号保护。（2026-10-02 模式 B 实测一次通过、全程无滑块——但别把这当常态，滑块出现概率随时段/IP/频次变化）
9. 验证码时效很短：实测倒计时 177s（约 3 分钟），让用户看到短信立刻转告，超时作废重发。
10. 评论懒加载深：热门笔记评论数百条，"逐屏滚动+快照"要设上限（如 5 屏或 50 条），避免无限滚动烧时间。
11. **[实测] React 输入框必须原生 setter 填值**：小红书登录的手机号/验证码输入是 React 受控组件，locator.fill 表面成功但状态可能没进 React tree。可靠写法：
   ```js
   const setter = Object.getOwnPropertyDescriptor(window.HTMLInputElement.prototype, "value").set;
   setter.call(input, "文本");
   input.dispatchEvent(new Event("input", { bubbles: true }));
   ```
12. **[实测] 笔记直链必须带 `xsec_token`**：搜索结果里笔记链接自带 `?xsec_token=AB...&xsec_source=...`，把 id 拼成裸 `/explore/<id>` 直开=报"当前笔记暂时无法浏览"**并触发滑块验证码**。正确做法永远是回搜索结果页点击卡片。误触滑块后正常回搜索页浏览，滑块会自行消失（实测），不必慌也不必去拖。
13. **[实测] 笔记日期无年份**：近期笔记/评论只显示 `MM-DD`，跨年才是完整日期——落盘时按"抓取日期-显示日期"推算年份并标注"推算"。

## 通用

14. **[实测] IAB 内 Bing 会 302 到 cn.bing.com**：URL 写 `www.bing.com` 实际落在 cn 版，结果集有差异；cn 版无结果时可试明确 `https://global.bing.com`（新版路径可能变动，以实际为准）。
15. 凭证安全：手机号/验证码只出现在会话对话里，**禁止**写进任何落盘文件（评分卡、probe.md、日志均不允许）。
16. 会话 cookie 随 ZCode 进程存活，跨会话不保证——每次任务先探测登录态（B0），不假设、不提示用户"已登录"。
17. web_search 工具限流（429/1302）是常态（2026-10-02 遇到），发现类查询优先用浏览器 Bing 页面而非搜索 API。

## 2026-10-02 深夜首战深挖新增（闫继宏/郭霞两案例实测）

17. **[实测] 登录态跨会话存活**：白天模式 B 登录后，深夜**新会话** B0 探测直接已登录（侧边栏通知/消息/我齐全）——IAB WebView2 profile 落盘，旧条目 16 的"跨会话不保证"修正为"跨会话存活；完全重启 ZCode 后待冷启动复测"。用户手机验证码只需输入一次的诉求成立。
18. **[实测] 缩写检索标题层无效**："北邮 gx 导师"/"哈工大 yjh 导师"标题层全部泛命中（16-17 条均无具名）——缩写口活在**笔记正文与评论区**，标准动作=进院系维选导帖后用 evaluate 取 innerText 做 indexOf grep（姓名全称+缩写大小写）。
19. **[实测] domSnapshot 在小红书太重**：搜索页/笔记页快照 400+ 行（侧边栏占 70%），改用 evaluate 提取器：搜索页抓 `a[href*="/search_result/"]` 的 id+标题 Map；笔记页抓 `h1.closest("section").innerText`——上下文省 90%。
20. **[实测] 知乎专栏+问答匿名可读面比预期大**：专栏正文、评论区、问题页前 3 个回答+问题评论区全部未登录可读；折叠回答（"6 个回答"只显示 3）不硬刚，留缺口即可。
21. **[实测] "展开 N 条回复"按钮 div/span 混杂**：知乎评论区展开按钮在 button 上（原生 click 可用）；小红书子回复展开是 div/span，需正则 `/^展开\s*\d+\s*条回复$/` 批量 JS click。
22. **落盘 cwd 陷阱（agent 层）**：Bash 工具 cwd 会漂移，heredoc 写文件一律用绝对路径；本次 social_evidence 曾误落 workspace 根目录且清理时误删唯一副本，靠上下文重写恢复——**大段落盘前先 `pwd` 确认，写完立即 `ls -la` 验证**。
23. **[实测] 调研子代理无浏览器控制权**：subagent 环境没有 IAB/mcp__node_repl 工具，小红书/知乎评论路线对其不可用（多案例报告缺口节自注"建议主会话补采"）。**小红书补采=主会话批量职责**：当前待补名单=王新兵/何晖光/Haoran Xie（+后续岭南 20 人），模式=站内搜姓名+学校变体→标题提取→进帖 grep，每批顺路做掉。

## 2026-10-03 上午批量补采新增（r1 批次实测）

24. **[实测] 登录态完全重启 ZCode 进程后仍存活**：新会话 B0 探测直接已登录——条目 17 的"完全重启待复测"升级为**成立**（WebView2 profile 磁盘落盘确认）。B0 探测习惯保留即可。
25. **[实测] 笔记直开的"必须点击"收敛为"必须带 token"**：从搜索结果页 evaluate 提取带 `xsec_token` 的 href 后，直接 `goto` `/search_result/<id>?xsec_token=...` 可 200 打开（会 302 到 `/explore/<id>?xsec_token=...` 形态）——省一次点击。裸 `/explore/<id>`（无 token）依旧 404+滑块，铁律不变。
26. **[实测] 从笔记页直接 goto 搜索 URL 会导致结果流不渲染**（SPA 状态未重置，复现 2 次，页面只剩侧边栏+页脚）——**必须先回 /explore 停 ~1.5s 再进 search_result**。
27. **[实测] 笔记弹窗正文可能不渲染进 innerText**（图片/视频型笔记或懒加载失败）：head 段只有页脚+ICP 备案=文本层不可达信号，此时 **grep 命中与否都不可信**，只能记"不可核"，禁止记"无涉及"。校级"红黑榜/避雷帖"多为图片表格型，文本 grep 通道天然受限。
28. **[实测] 人名被搜索拆词吞没**：单名"雷州"（=地级市）、生僻姓氏首字（"初剑峰"→"初"字义项）在站内/引擎两侧都会命中同名泛词内容——具名零命中必须换"学校+导师避雷/评价"校级词+进帖 grep 复核后才可下"未找到"结论。
29. **[实测] 导师本人/团队科普内容运营是小红书结果面的常见形态**（何晖光案例：18 条结果几乎全为其团队概念表征/脑机接口科普）——按 skill 红线属旁证不计分，但可作为"该导师在小红书有内容存在"的线索记录。
