# AI 导师评价库

> **透明、可复算、可自托管的研究生导师评价体系** —— 我们开源的不只是一个网站，更是「怎么用 AI 调研导师」的整套方法。

*Open-source advisor scorecards & AI research skills for CS/AI grad-school applicants in China.*

选导师是读研路上信息最不对称的一步：官方主页只写成果，学长学姐的口口相传覆盖不了多少人，前人做过的评价网站要么被关停、要么变成了收费站。这个项目用两条腿走路：

- **轨道 A · 评价平台（本仓库 `site/`）**：481 所高校、42,478 位导师的证据链评分卡。纯静态站点，克隆即可本地跑、可自托管、可镜像——**数据和方法全部开源，任何人都可以复算每一分是怎么来的**。
- **轨道 B · AI Skills（本仓库 `skills/`）**：7 个 Agent Skill，装进你的 AI 编程助手（Claude Code / ZCode 等支持 skills 的 agent），它就能按同一套方法论**调研任何一位导师**，输出带来源、带日期的结构化报告。网站没覆盖的老师，你自己动手就能查。

两条轨道共用同一套[评价维度与评分口径](docs/dimensions.md)：你用 skill 调研出的结果，和站内的评分卡是同一个标准。

**不会编程也能用，两种零门槛方式（推荐普通用户从这里进）：**

| 方式 | 入口 | 适合 |
|---|---|---|
| ① 开网址 | <https://open-advisor-review-org.github.io/open-advisor-review/> | 有网就能看，数据最新，手机电脑均可 |
| ② 离线单文件版（**推荐**） | [Releases → offline-latest](https://github.com/open-advisor-review-org/open-advisor-review/releases/tag/offline-latest) 下载 `advisor-review-offline.html`（约 23MB） | **双击**即用浏览器离线打开全部数据；微信/QQ/网盘直接传这一个文件给同学；数据是构建时的快照，页面顶部标注版本，想看最新回线上版 |

![线上版二维码](docs/qr-online.png)

> **为什么更推荐离线版**：线上版托管在 GitHub Pages（海外免备案托管），国内访问时快时慢，且平台对站点有**每月 100GB 的流量软上限**——访问高峰期可能变慢甚至暂时打不开，这多半不是站点坏了。离线版数据与线上版同源同版本，不联网、不受带宽限制，下载一次随时能用；数据更新后重新下载即可（下载入口链接固定不变）。

### 路径一（开发者 / 自托管）：克隆本地跑或镜像

```bash
git clone https://github.com/open-advisor-review-org/open-advisor-review
cd open-advisor-review/site
python -m http.server 8799
# 浏览器打开 http://127.0.0.1:8799
```

站点是纯 HTML + 原生 JS，无构建、无依赖，数据（`site/assets/api/`）已内置。主要页面：

- **数据大盘**：全库分布、评价时间线、七维均分、院校层级
- **学校榜单**：按学科切桶（默认「AI 方向汇总」，可切 LLM / CV·NLP / 机器人 / 传统ML / 网安 / 其他CS 等），支持院内筛选与 QS 排名参考
- **导师评分卡**：综合分组成与权重瀑布、九维雷达、**逐维证据引用（评价原文）**、实习/退学硬信号计数、AI 综合判读、调研截止时间、原始评价存档；**方向前途带定档来源标注**（深挖调研定档 / AI 读论文定档 / 规则锚点初评）；零口碑导师展示「AI 资料初评」（资历/方向锚点 + 论文实锚）
- **评分方法论 / 加入我们**：评分口径与三条声明、学科打分配置、共建入口与联系方式

托管到 GitHub Pages：仓库已附带部署工作流（`.github/workflows/pages.yml`，部署 `site/` 子目录），到 Settings → Pages 把 Source 选成 **GitHub Actions** 即可。也欢迎镜像。

### 路径二：装上 skill，让 AI 帮你调研任何导师

Skill 遵循 Agent Skills 标准（一个文件夹 + `SKILL.md`），支持 skills 目录的 agent（Claude Code、ZCode 等）可直接安装；其他 AI 工具也可以把 `SKILL.md` 当作规则/提示词文件喂给 agent。

```bash
# 全局安装（对所有项目生效）
mkdir -p ~/.claude/skills
cp -r skills/* ~/.claude/skills/

# 或只在当前项目生效
cp -r skills/* <你的项目>/.claude/skills/
```

然后对 AI 说：

```
帮我调研一下浙江大学的 XXX 老师，我想报他的研究生
```

agent 会自动进入 advisor-research 流程：官方主页 → 学术库（DBLP/S2/OpenReview）→ 某乎/小某书风评 → 生成一份**每条结论带来源 URL 和日期**的调研报告；查不到的写「未找到」，禁止编造。

## Skills 一览（7 个）

| Skill | 干什么 | 什么时候用 |
|---|---|---|
| `advisor-research` | 单导师结构化调研报告 | 「这位老师怎么样 / 值不值得报」 |
| `advisor-scorecard` | 单导师十项评分卡（七维口碑 + 实习 + 退学 + 方向前途） | 「给这位老师打分 / 出评分卡」 |
| `advisor-scorecard-batch` | 批量出卡的三级分层管线（深扒 / 轻调研 / 库内口径） | 「把某校主要老师都出卡」 |
| `advisor-social-mining` | 某乎 / 小某书评论区导师口碑挖掘（含登录墙实测路线） | 「去社交平台搜这位老师的风评」 |
| `advisor-roster` | 逐校抓取官方导师名录的 agent 爬虫 | 「建某校导师库 / 名录增量更新」 |
| `advisor-profile` | 导师研究方向画像（学科级 → 主题级关键词细化） | 「补全/细化导师的研究方向」 |
| `scrape-flow` | agent 网络采集通用流程（探路检查点 / 断点续跑 / 坑清单） | 任何批量抓取任务的底座 |

`data/roster/roster_patterns.json` 是 62 所学校官网导师库的**实测入口模式库**（每校每院的入口 URL、WAF 形态、解析坑），由 agent 爬虫逐校跑出来的经验沉淀，配合 `advisor-roster` 使用。

## 评分口径（与站点、skill 三方同源）

```
综合分 = ( 七维口碑均分 × 0.55 + 实习放行 × 0.15 + 退学风险 × 0.15 + 方向前途(AI评) × 0.15 ) / Σ权重
         − 红线阶梯扣分（不放实习 −1；延毕指控 硕 −2.5 / 博 −1.5；退学硬信号 −6，可叠加）
```

- 任一条评价即出综合分；缺项按剩余权重归一化；只有综合分可以为负
- **采信原则：单条负面评价即采信计入**（保守优先——评分卡用于学生的前途决策，误判代价不可逆）；负面证据不随时间衰减
- 每张评分卡强制标注三个时间：生成时间 / 库内评价跨度 / 调研截止；6 年以上的旧评标 [旧评]
- **口碑信号 AI 审计**：退学/延毕类词命中与"低分评论被打出正面维度分"的评论，经 AI 逐条判决（否定句/条件句/反讽/对象误指/引述等误计家族撤销，真实信号维持）+ 人工终审抽查；判读留痕全量可重算
- 完整设计见 [docs/scorecard-design.md](docs/scorecard-design.md) 与 [docs/dimensions.md](docs/dimensions.md)

**三条不可让步的声明**（站点页面与 skill 输出共同遵守）：

1. **不输出「建议报 / 不建议报」的裁决**——只呈现证据与信号，决策留给你自己；
2. 实习放行 / 退学风险 = **未经证实的网络评价统计**，不是事实认定；
3. 方向前途分 = **AI 判断，非客观测量**。定档金标准 = **AI 读导师近 5 年论文**（DBLP 论文实锚 → 总结主研究方向 → 按 rubric v2.2 定档：当前最热主赛道基准 4.0 / fit 高 4.5 / 顶线头部 5.0 罕见封顶；传统优化 ≤2 / 传统 ML ≤2.5 / CV·NLP 经典 3）；无论文证据时用关键词锚点兜底并在卡上标注。每张卡的打分依据（主桶、fit、论文题名证据）随卡公开；AI 判读未能定档者在卡上如实标注原因。

## 红线与脱敏（法律安全设计）

这个项目从第一天就按「可能被盯上」来设计（前人网站的下场见 [SURVEY.md](SURVEY.md)）：

- **凡触发红线扣分的导师，站点数据层一律匿名**：显示为「姓氏 + 拼音首字母」（如 张L、李LH），姓名在全站所有展示面遮蔽，不内嵌其调研报告全文、不外链官方主页；评分拆解、证据引用、信号计数功能完整保留
- 不设任何「负面名单」榜单；正面高分样本保持实名
- 平台不存实名指控；师德类指控只链官方来源，不复述细节；学生姓名只计数、不呈现
- 所有评分可复算：评分标准变更时凭原始证据重算，不需要重新调研

如果你是导师本人或知情者，认为某张评分卡信息有误，请通过 [Issue](../../issues) 或站内「加入我们」页的联系方式提交**可溯源的官方证据**，我们会按「证据可溯源 + 冲突并列呈现」的规则处理（见 [CONTRIBUTING.md](CONTRIBUTING.md) 的验收规则）。

## 数据来源与边界

站内数据来自三类公开来源，**处理边界各不相同**：

| 来源 | 规模 | 边界 |
|---|---|---|
| 历史匿名评价存档（原导师评价网 2014–2020、urfire 2022 等） | 39,739 条 | 原始存档**不随本仓库分发**（版权属原作者）；仓库内发布的是从中合成的评分、信号计数与逐维度摘录（红线导师已遮蔽） |
| 各校官方师资名录 | 29,290 条 | 公开官方信息，agent 爬虫采集（方法见 skills）；**目前覆盖 72 所 AI/CS 重点校**，其余学校的导师列表仅含评价存档中出现过的导师 |
| 全网公开调研（某乎 / 小某书 / 官方页 / 学术库） | 2026-10 现势证据 | 每条结论带 URL + 日期，落盘存档可复算 |

不随仓库分发的还有：`refs/` 下的四个历史数据镜像（均无 LICENSE）、原始管线工作区。仓库内 `site/build.py` 是从上游数据产物重建站点 JSON 的构建脚本，本仓库已内置其构建产物，通常不需要重跑。

### 覆盖度说明（哪些数字是全量、哪些在推进）

- **评价存档**（39,739 条）覆盖 469 所学校，加上官方名录新增的 12 所，这是「覆盖高校 481」的口径
- **官方师资名录**只深挖了 **60 所** AI/CS 方向重点校——这些学校有完整（或接近完整）的师资名单
- **其余 409 所学校的页面**只列出评价存档中出现过的导师（即「被人评价过的老师」），**不代表该校全部师资**；某校只显示几位导师是采集进度问题，不是该校就这么多老师
- 名录、方向画像、深挖报告都在分层推进中，欢迎用 `advisor-roster` skill 帮你学校补一份名录（见 CONTRIBUTING）
